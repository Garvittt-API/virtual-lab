# Research decisions and open questions

**Decision type:** recommendations for implementation; none were applied in this research task. Evidence and status are in [CURRENT_ARCHITECTURE_AUDIT.md](CURRENT_ARCHITECTURE_AUDIT.md). The product reference is user-supplied; no browser-based comparison was performed.

| Decision | Recommendation and reason | Alternatives / trade-offs |
|---|---|---|
| One authority | One versioned canonical state per independently saved attempt; inventory lives in workspace compartments only; React/Three project it. Guided/free differ by policy + initial manifest. | Synchronizing separate mode stores creates conflict and hidden copies; one global bench would mix independent attempts. |
| Existing engine | Extend `lab/engine.js`/`reactions.js`, preserve tests and UIs; migrate in bounded increments. | Rewrite from scratch risks loss of saved data, science and established functionality. Wrapping unchanged legacy states is not full unification. |
| Command semantics | Typed pure command application and atomic domain result, consistent validation and explicit model capability errors; commits integrate state/progress/notebook. | Direct React writes or storing derived visuals as scientific truth are simpler but bypass safety/history and can diverge. |
| Phase and chemistry | Model phase/compartment amounts with explicit model limits and unknowns; derive concentration; specify inventory conventions with reviewer. | Assigning densities, temperatures, solvent moles or gas amounts to absent data fabricates science. Full general-purpose chemistry is not currently justified. |
| Reaction engine | Keep balanced stoichiometry kernel; layer approved process models and versioned parameters. | Guessing outcomes from formula similarity or treating balanced equations as kinetics/equilibrium is invalid. |
| Oxygen mapping | Preserve legacy original, map fixed 1 g and known conversion fractions into explicitly labeled ideal solid/product/gas states; compare every step and 22.414 L/mol at 0 °C/1 atm. Require scientific review before declaring equivalence. | A new heat simulator would change model; representing only a progress counter in a wrapper is not canonical inventory. Historical undo and exact times not in saved data cannot be reconstructed. |
| Legacy neutralization | Derive acid/base initial totals from stored `baseMl` and manifest, apply the known 1:1 reaction once, preserve pH derived at 25 °C and note that this is reconstructed; retain originals. | Treating initial totals as unreacted then also storing products double-counts atoms; guessing saved answers/history is unacceptable. |
| Manifest safety | Data-only, versioned, validated schema with bounded allowlisted predicates and role references, model capabilities and safety acknowledgements; pin manifest/model versions per session. | Executable user JS/eval offers flexibility but is unsafe and hard to reproduce; experiment-specific branches do not scale. |
| Storage | Recommend IndexedDB for transactional session + notebook records, async repository and user-visible recovery/export. Copy localStorage sources and verify target before activation; never delete originals automatically. | Per-key localStorage is currently simple but cannot atomically commit multiple keys and history. IDB is not a backup; durability and eviction remain concerns [1](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction). Backend sync adds privacy and operational costs; defer. |
| Notebook | Shared versioned structured events linked to durable session IDs; user observations outside undo snapshots; record undo/redo separately. | Delete events on undo loses provenance; shared free-text log alone lacks quantity, stable session IDs, reliable transactional write and all activities. |
| Scene | Reuse Three.js assets/OrbitControls/Raycaster while extracting persistent scene/projection; previews transient, commit through command. | Recreate all scenes or install a full rigid-body/CFD engine prematurely; animations must not determine inventory. |
| Interaction access | Always offer click/tap and keyboard alternatives to drag and a 2D/list fallback. WCAG dragging alternative is distinct from keyboard accessibility [1](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html). | Drag-only interactions exclude users; full accessibility cannot be inferred from lint or code. |
| Content/data governance | Curated versioned resource records with original/licensed assets, provenance, model support and human review; ingest properties with conditions and uncertainty. | Bulk placeholder experiments or unrestricted ingestion makes unsupported and hazardous simulations appear verified. |

## External technical research and applicability

- Three.js documents orbit, dolly and pan in `OrbitControls` [3](https://threejs.org/docs/pages/OrbitControls.html); reuse is a design choice, not verification of this app. Its instancing documentation describes reduced draw calls for many identical geometry/material instances [3](https://threejs.org/docs/pages/InstancedMesh.html); profile before applying.
- MDN describes pointer capture, `pointercancel` and touch-action [1](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events); current code uses these APIs but actual gesture behavior remains untested. MDN describes transaction boundaries and durability caveats [1](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction).
- IUPAC defines reaction extent [1](https://goldbook.iupac.org/terms/view/E02283); it does not justify assuming complete reaction, rates or equilibrium. Existing atomic-weight provenance is documented in `substances.js`; molar volume in legacy `oxygen.js` is an ideal 0 °C/1 atm assumption, not independently reviewed here.
- PubChem describes aggregated physical/safety information and source organizations [4](https://pubchem.ncbi.nlm.nih.gov/docs/compound-page); NIST examples include reference conditions and uncertainty [2](https://webbook.nist.gov/cgi/cbook.cgi?ID=C7727379&Mask=4). Neither automatically validates the app or supplies a mixture-level hazard assessment. Check each selected dataset's provenance and usage terms.

## Open questions before implementation

1. Who owns scientific review, per-model acceptance ranges, data quality, hazard classification across jurisdictions and age groups? Which experiments are in the initial reviewed curriculum?
2. Session/controller semantics: may a learner switch an active guided session into open/free policy and back, or only fork it? How should required steps behave after off-procedure actions? Roadmap recommends testing the same ID across policy changes but product must approve policy and progress rules.
3. Which precise physical phases/compartments and solvent representation cover liquid, oxygen and later apparatus without pretending unsupported thermodynamics? What provenance model marks unknown values and legacy reconstruction?
4. Which migration inputs deserve automatic conversion versus opt-in preview? Legacy oxygen and neutralization do not record history timestamps, durable answer state or a persistent undo stack. How should ambiguous/corrupt state be presented and exported?
5. Storage policy: IndexedDB support targets, quota/eviction handling, cross-tab conflict behavior, retention, backup, encryption/privacy needs, and whether any backend synchronization is authorized.
6. Instrument precision and uncertainty, units and rounding policy, validated calibration curves, units for persisted quantities, and appropriate conservation tolerances.
7. Which browsers, touch hardware, accessible interaction targets, fallback UX and measurable performance budgets? This environment cannot verify these.
8. Manifest authoring ownership, review/version rollback and licensing; permission model for sharing templates and classroom-created content.
9. Student/teacher ages, curriculum, localization, assessment scoring and privacy/consent requirements; local-only today.
10. Animation fidelity versus scientific model support, and how prominently the UI differentiates qualitative illustration, educational simplification, numerically verified behavior and independently reviewed science.
