## Answers, backed by code and tests

1. **One canonical state? No.** `src/lab/engine.js:4-5` defines `LabState` `{objects,connections,events}` and `Vessel` `{id,kind,position,volumeMl,solutes,solids?,mixed?}`. A single vessel state is authoritative within a given workspace. Guided stores `{version,core:{workspace,experiment:{id,step,notes}},past,future}` (`guided.js:176-193`); free stores `{version,createdAt,workspace,past,future,notes}` (`free.js:3-13`). Liquid workspace is another state; legacy oxygen stores `{connected,loaded,steps,notes,positions,events}` (`oxygen.js:10-16`); legacy neutralization stores `{baseMl,positions,notes,events}` (`main.jsx:50-61`). `simulation/runner.js:205-218` has a separate flat `{inventory,volumeMl,...}`. There is no common active session or global scientific inventory.
2. **Guided/free same session? No.** `GuidedLab.jsx:12-18,124-136` reads/writes `materia-guided-v1`, `FreeLab.jsx:12-19,21-42` uses `materia-free-v1`. Both use `LiquidScene` and `executeCommand`, but independently mount, save and track history. Switching modes does not hand over a session. `tests/core-increment.test.js:25` compares equivalent vessel values, not shared identity or continuity.
3. **Inventories shared? Not across sessions.** Both invoke `executeCommand` → `execute` (`engine.js:301`, `guided.js:283`, `free.js:87`), each on its own workspace. Scene receives props; it does not synchronize inventories. `LiquidLab.jsx:10-42` directly uses `execute` on `materia-liquid`; legacy oxygen and neutralization have different models. `tests/unified.test.js:32-64` verifies guided inventories, not cross-screen sharing.
4. **One command API? No.** `execute` is throwing, immutable workspace command; `executeCommand` converts units; guided `dispatch` and free `dispatchFree` return `{ok,state,error}` and separately implement undo/reset/notes. `oxygenTransition` returns old state on invalid operations; `main.jsx:395-415` updates base volume directly; `runner.js:222` is another transition API. UI can bypass a universal policy/transaction boundary. `tests/lab.test.js` verifies common workspace checks, not all flows.
5. **One runner? No.** `guidedManifests` and `dispatch` (`guided.js:11-173,242-305`) execute 3 vessel sequences; fixed required IDs `a,b,f`, action types and guided setup validation constrain extensibility. `simulation/runner.js:7-133,196-278` has four in-memory, fixed calculation-only manifests and flat inventory; `ReactionExercises.jsx:11-43,61-62` uses them separately. Legacy `experiment.js` and `oxygenTransition` are additional procedural flows. `tests/runner.test.js` does not prove workbench execution.
6. **Every experiment structured? No.** Three guided manifests and four calculation definitions are partially declarative; `experiment.js:2-38` has legacy educational data and questions; oxygen UI/operations and `oxygen.js` hardcode workflow/equipment. No common schema for initial instances, requirements, safety acknowledgement, assessment, custom experiments or general completion; no safe authoring pipeline.
7. **Oxygen migration without losing behavior? Feasible in principle, not implemented or proven.** Preserve `connected`, `loaded`, 0–5 steps, tube/burner/jar transforms, notes/events, current proximity rule and ideal conversion. `oxygenYield` uses shared reaction with 1 g / 122.55 g mol⁻¹, 20% increments and 22.414 L mol⁻¹ at 0 °C/1 atm (`oxygen.js:3-40,75-97`), complete capture. `engine.js:75-90,213-237` admits only specified dissolved species and AgCl solids, no gas, tube/burner/collector or chlorate-loading operation. Converting values requires explicit provenance and equivalence tests at all 6 steps; old sessions contain no persistent undo stack, original timestamps or assessment answers. Preserve unknown data rather than invent it. `tests/oxygen.test.js` tests the old state machine, not migration.
8. **Legacy neutralization migration without losing behavior? Feasible with conditions, not implemented.** `main.jsx:50-89,395-415` stores total base volume and transforms; `chemistry.js:8-41` computes pH at 25 °C using charge balance and shared `react`, not vessel state. The mapping must reconstruct tracked total acid/base and reacted products once, keep 0–50 mL and exact pH behavior, positions, notes/events, and avoid double reaction. UI assessment is React-only and old persisted data has no answers or timestamps. Test 0, each increment and endpoints; preserve original key and record inferred inventory, not fabricated measurement history. `tests/chemistry.test.js`, `tests/experiment.test.js` validate calculations/questions but not mapping.
9. **AgCl/dilution same workbench? Partially now.** `guided.js:52-117`, `engine.js:178-249`, `GuidedLab.jsx:260` use actual vessel state with `LiquidScene`; free mode can use the same command engine, but doesn't open the same guided session. `tests/unified.test.js:46-64`, `interactive.test.js:42,140` check reaction/dilution values. Dilution uses 100 mL volumetric definition but no meniscus, pipette or actual measurement precision; AgCl conversion is ideal complete, not Ksp.
10. **Notebook suitable for all? Foundation only.** `notebook.js:2-93` stores validated version-1 free-text event/observation entries, manual edits/removal and text/Markdown export. `GuidedLab.jsx:129-169` and `FreeLab.jsx:35-74` append after session writes, generate view-local UUIDs (not durable session IDs), so no atomic write with simulation, no concurrency control or guaranteed multi-tab history. Legacy screens and calculation exercises do not append automatically. `import-notes.js` copies notes/events (not scientific sessions); deduplicates by source key/kind/index, skips changed content at same index, uses import time; guided/free validated, legacy only notes/events fields validated. `core-increment.test.js:74-162` covers notebook/import success and failed import, not UI, cross-tab or transactional recovery.
11. **Save/reopen arbitrary custom workbench? Partially.** `free.js` supports one 12-object, local version-1 workspace and 50 snapshots; `FreeLab.jsx:12-42` resumes that key, not a list of named custom sessions/templates or export/import of full state. Invalid saved JSON falls back to empty state in `read()` and later `put()` can overwrite original; same pattern in guided/legacy. No migration/recovery UI or localStorage quota handling for simulation saves. Free notes remain separate from action undo; guided snapshot `core.experiment.notes` can roll back (new activity notebook is separate). No backend/accounts/sync.
12. **Connections/physical interactions? Limited.** `registry.js:4-61` has five apparatus definitions, capability lists and reciprocal typed ports; `engine.js:93-119,260-275` validates port existence/compatibility/occupancy and logical connect/disconnect. `tests/lab.test.js:51,95` tests these cases. No spatial alignment/snapping, clamp/stand or flow path. `LiquidScene.jsx:142-155` draws an illustrative connection; free UI does not expose connect (`INTERACTIVE_LAB.md`). Placement checks simple center distances; `move` checks bounds but not overlaps (`engine.js:127-148,276-288`).
13. **Realistic transfer blockers.** `engine.js:178-204` instant proportional solute transfer with selected volume, no spout, tilt, path, mixing gradients, viscosity, spill, pipe flow, rate or pressure. Solvent mass not tracked; solid stays behind (`tests/unified.test.js:110`). `LiquidScene.jsx:104-121` visual liquid level is proportional fill approximation, not calibrated vessel geometry; selection drag moves object on a horizontal plane (`:157-205`), not pouring. Visual animation cannot repair missing physics/chemical models.
14. **Disposition:** retain/extend pure `react` and validated conversions, vessel command conservation and registry, existing source data, working screens, test fixtures and `LiquidScene` procedural assets; consolidate guided/free session orchestration, command results and notebooks around a canonical store; adapt `LiquidLab`, `OxygenLab`, legacy `main.jsx` and calculation exercises progressively. Refactor scene lifecycle/selection and registry separately; replace duplicate workflow logic only after compatibility and migration checks pass. Do not overwrite old keys or delete legacy screens while migration is unverified.
