# Laboratory core consolidation — partial, not acceptance-complete

## Current architecture

The workspace format (`lab/engine.js`) represents equipment instances, positions/rotations, connections, liquid volumes, dissolved molar inventories, settled AgCl and simulation event strings. It is independent of React/Three and is the authoritative vessel inventory **within each** guided or free session. The shared `executeCommand` normalizes volume units and delegates to the existing immutable `execute` command engine; guided and free dispatchers now both use it, including a validated concentration measurement command. Commands clone before execution and invalid commands leave inputs unchanged. Both modes render their own workspace with the same `LiquidScene`. This does not mean there is one application-wide active session: guided and free still persist separate workspaces and have different history structures.

The three guided manifestations use `lab/guided.js` for progression and the common vessel/reaction engine. Guided steps prescribe required operations and IDs while permitting student volumes. `simulation/runner.js` remains a separate, calculation-only runner. Oxygen and legacy neutralization still use their own activity state and UI, though their stoichiometry delegates to `simulation/reactions.js`. Neither runs on the guided vessel inventory. The oxygen model stores a conversion count instead of a solid/gas vessel inventory; the legacy neutralization model stores base volume and computes pH on demand. The current liquid engine accepts only aqueous solutes and AgCl solids; its equipment registry has no reaction tube, burner or gas collector. Consequently blindly translating oxygen to these vessels would discard equipment, thermal-operation semantics, progress or collected gas. A validated, lossless canonical solid/gas model and explicit reversible migration are still required before replacing those activities.

## Notebook and persistence

`lab/notebook.js` supplies a versioned `materia-notebook-v1` store for new guided and free activity entries and manual observations. It validates before writing; undo/redo changes simulation snapshots but does not remove notebook entries. The new Activity notebook provides edit/remove observations and text/Markdown export. It records available engine event strings and undo/redo/reset notices; it does not yet structure all equipment, measurements, calculations, assessments and completion records. A random activity-view identifier groups entries while a screen is mounted; it is not yet a durable simulation session ID across reloads. Browser storage is not transactional across the simulation and notebook: a failed notebook write leaves a saved action and shows an error. Concurrent tabs can overwrite notebook changes. Legacy separate notebooks and local stores remain intact.

The explicit import action copies note/event text from valid guided and free saves, and from the notes/events fields of legacy oxygen and neutralization saves, without modifying originals. Guided/free source sessions are fully validated; oxygen/neutralization imports validate only their notes/events fields, not scientific state. It imports no scientific inventory or progress. Repeated import skips an already imported source key/type/index; if a legacy entry later changes at the same index it will not be refreshed. Imported records use import time, not original event time. If any source cannot be read or validated, no notebook write occurs. Old keys (`materia-guided-v1`, `materia-free-v1`, `materia-oxygen`, `materia-session`, and `materia-liquid`) have not been migrated to a unified session or overwritten by import. Existing activity UIs continue their original storage behavior.

## Measurement and scientific limits

Volumes are in mL internally, with mL/L input conversion. The measurement command records calculated concentration from tracked dissolved moles divided by total volume, not a physical instrument reading; solvent water moles are not tracked. Mass/mole entry, temperature, physical measuring instruments, heat/cooling, gas collection, realistic fluid flow and measurement uncertainty are not implemented in the shared workspace. Existing oxygen yield retains 122.55 g/mol KClO3 and 22.414 L/mol ideal gas at 0 °C and 1 atm; rounded atomic weights and their IUPAC provenance are in `simulation/substances.js`. Acid/base assumes ideal complete reaction, additive volumes and (for legacy pH) 25 °C water autoionization; AgCl precipitation assumes complete conversion without Ksp/equilibrium. No kinetics, realistic heat or pouring is modeled. These are educational simulations, not physical procedures, and have not received independent scientific review.

## Remaining acceptance work

Define a single versioned session and stable persisted IDs, canonical physical-state inventories (solid, liquid, gas), typed commands/results and notebook history; safely adapt the existing UIs and old saves without erasing source data. Consolidate both runners and port oxygen, legacy neutralization and the three guided experiments to one data-driven runner. Add safety checks, assessments, calculation steps, completion/history, practical measurement and instrument policy, and true data migrations with rollback and tests. Remove parallel scientific session stores only after validated migration and compatibility verification. Until then this is a partial increment, not ONE laboratory platform.

## Guided/free canonical session increment (2026-11-14)

`lab/session.js` now owns version-2 `{version,id,name,mode,createdAt,updatedAt,core:{workspace,experiment},past,future,notebook}`. The only current scientific inventory is `core.workspace.objects[*]`; concentrations are derived. Undo/redo stacks contain historical `core` snapshots, not a second current inventory. The session uses the existing workspace registry/stoichiometry engine; `experiment` is either `{id,step}` for the three guided manifests or null. Timestamps and entry IDs are supplied at the UI boundary; `dispatchLab(session,action,at,entryId)` validates, copies, invokes `executeCommand`, and returns `{ok,state,error}`. Actions include `perform`/`next`, `place`, `remove`, `move` (rotation included in position), `add`, `transfer`, `mix`, `measure`, `measure-volume`, `react`, `connect`, `disconnect`, `note`/`observe`, `edit-note`, `remove-note`, `policy`, `undo`, `redo`, `reset`. Failed actions preserve the original state and notebook. Guided policy requires an experiment and matching next step; free policy permits supported operations. Switching policy does not replace workspace, progress, ID or notebook. A free session without an experiment cannot enter guided mode; start a guided session explicitly. Free edits may make a guided procedure impossible on return; undo/reset or correct the equipment/quantities.

`SessionWorkbench.jsx` is the shared session selection/controller UI used by both navigation entries. It supports independent named sessions, experiment creation, free/guided policy buttons, notebook editing and text/Markdown export. It renders the existing `GuidedLab` or `FreeLab` against the same session; existing `LiquidScene` consumes the workspace. The global Activity notebook displays canonical session entries alongside its earlier `materia-notebook-v1` records; editing canonical observations happens in their session. Notebook events are recorded in the session atomically with state in the single saved record; notebook observations do not revert with simulation undo/redo. Existing old global notebook entries remain separately stored and are not automatically linked to new sessions because earlier view IDs are not reliable durable session IDs.

`lab/session-store.js` stores version-1 session collection under `materia-lab-sessions-v2` (containing version-2 sessions). It validates, then copies valid `materia-guided-v1` and `materia-free-v1` state, progress, workspace snapshots and current/historical notes/events into distinct stable migrated sessions, recording source-key markers to prevent duplicate imports. Unknown legacy object fields are rejected rather than silently discarded. Original keys are never written or removed by migration. Guided legacy creation time and event times were not stored: migration uses the import time, not claimed original times. Migrated historical guided notes are preserved in notebook, not reverted with simulation undo; exact legacy original remains in its old key. Unknown fields, malformed saves, unsupported versions and write failures stop import and present a recovery error; no fallback blank save is performed. Retrying a successfully imported source does not refresh a later change in that source; explicit conflict/change detection and re-import are not implemented.

The store is a single localStorage value to keep session and notebook writes together; this is not IndexedDB, a backup, or a multi-tab transaction. Concurrent tabs can overwrite each other; quota/eviction and blocked storage remain risks. It cannot reconcile old notebook view IDs, has no session JSON import/export, and no automatic repair/export UI for corrupted storage. `guided.js`/`free.js` v1 dispatchers remain for existing tests and migration compatibility but the two laboratory screens no longer call them. `LiquidLab`, oxygen, legacy neutralization, calculation-only runner and their scientific stores remain separate and have not been migrated. The shared policy runner is still limited to the three existing fixed-step manifests; free-mode connections are supported in the controller but not exposed as controls. Equipment without operations may still show controls that return an error. Simulation remains ideal: additive volumes, instantaneous mixing, complete reactions, AgCl without Ksp, no thermal/kinetic/fluid model; no independent scientific review.

Terminal tests exercise the controller and storage with in-memory storage mocks, not actual localStorage or UI. No browser or visual verification was performed; manual inspection must cover session selection, policy switches, guided/free scenes, legacy import/recovery, notebook editing/export, reload and mobile controls.
